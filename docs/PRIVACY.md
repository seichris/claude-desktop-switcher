# プライバシーと透明性

新しい環境ではCodeの会話・メモリ・入力履歴を共有する設定が既定です。作成時に不足している`projects/`と`history.jsonl`だけを用意し、CLIへサインインしません。ネイティブCodeサイドバー全体の共有は初回Desktopサインイン後に、アプリでバックアップと置き換えを確認して有効にします。既存の環境は自動移行しません。

上記の保存先の準備は、以下に記す従来のリンク作成だけの動作の例外です。共有元に不足する会話保存先だけを作り、保存先のディレクトリを非公開にします。認証の保存先は開きません。


Claude Desktop Switcher（以下CSW）が、あなたのMacの何を読み、何を書き、何に決して触れないかを、この文書にすべて列挙します。あわせて、それが守られていることをあなた自身の手で確かめる方法を載せます。「安全です」と宣言するだけでは、確かめようがないからです。

この文書に書いた内容は実装と同期させています。実装を変えるときはこの文書も同じ変更で更新し、食い違いがないかをリリース前の点検で確認しています。

## 4つの約束

1. **インターネット通信を行いません。** 利用状況の送信も、自動アップデートの通信もありません。
2. **パスワードやサインイン情報を読み取りません。** パスワードを保管するmacOSのキーチェーンに触れず、サインインのトークンやブラウザのCookieの中身を開くこともありません。環境を複製するときは、Claude Desktop AppのCookieなど、複製で写す対象に含まれるサインインのファイルも、ほかのファイルと同じように、中身を開かずにそのまま写します。詳しくは下の「環境の複製について」で説明します。
3. **読むローカルデータを限定し、公開します。** 共有やコピーでは、あなたが選んだ項目だけに触れます。加えて、Claudeの利用量の画面は、Claude Desktop Appが保存した利用量の履歴と、対応する利用量の応答のキャッシュを読みます。利用量を得るために会話やサインイン情報を読まず、既存のClaudeのデータを書き換えません。
4. **シェルやOSの設定は変更しません。** Codeを共有する環境の作成では、共有元に不足する会話保存先だけを用意します。シェルの設定ファイルやOSの環境変数は変更しません。既存のClaudeは、ローカルCode全体の共有を明示的に有効にした場合だけCodeストアを置き換え、サインイン情報は対象外にします。CSWを使わない起動では、その時点のストアを使い、新たな同期は行いません。

## 通信について

CSWはインターネットに接続しません。接続する仕組み自体を持っていません。

唯一の例外は、画面下部にある「ユーザーガイド」「問題を報告」「更新を確認」の3つのリンクと、「このアプリについて」の画面にある「確かめ方を見る」と、cswコマンドの入手先を案内する「リリースページを開く」です。これらを押すと、あらかじめ決めてあるGitHubのURLをmacOSに渡し、既定のブラウザで開きます。通信するのはブラウザであって、CSW自身ではありません。「ユーザーガイド」と「確かめ方を見る」は、表示言語に応じて日本語版か英語版の文書を開きます。「リリースページを開く」は、初回の案内、詳細画面のターミナルの説明、分離の検査の結果に表示され、「更新を確認」と同じリリースページを開きます。渡せるURLは次の6つに固定してあり、実装のうえでも`https`以外のURLを拒否します。

- `https://github.com/matsumotory/claude-desktop-switcher/blob/main/docs/USER_GUIDE.md`
- `https://github.com/matsumotory/claude-desktop-switcher/blob/main/docs/USER_GUIDE_EN.md`
- `https://github.com/matsumotory/claude-desktop-switcher/issues`
- `https://github.com/seichris/claude-desktop-switcher/releases`
- `https://github.com/seichris/claude-desktop-switcher/blob/main/docs/PRIVACY.md`
- `https://github.com/seichris/claude-desktop-switcher/blob/main/docs/PRIVACY_EN.md`

更新の確認も同じ仕組みです。CSWが新しいバージョンを問い合わせるのではなく、GitHubのリリースページをブラウザで開くだけです。

## CSWが書く場所

既定では、自分専用のフォルダ`~/.context-switcher-claude/`の中に書き込みます。環境の削除では、その環境のフォルダをmacOSのゴミ箱へ移動します。ローカルCode全体の共有を明示的に有効にした場合は、既存のClaudeを含む参加環境のDesktopデータ内にある下記3つのCodeストアも置き換えます。サインインの保存先は対象外です。

| パス | 内容 |
|---|---|
| `~/.context-switcher-claude/config.toml` | いま選ばれている環境の名前 |
| `~/.context-switcher-claude/session.toml` | 前回すべて閉じたときに同時に開いていた環境の名前 |
| `~/.context-switcher-claude/native-code.toml`と`native-code.lock`と`.native-code.toml-*` | 明示的に有効にしたローカルCode共有の参加環境、生データと内容の指紋、各環境の直近16種類の内容の指紋、検証済みの環境とストアの保存先、最後に確認した参加環境の起動、操作のロック |
| `~/.context-switcher-claude/native-code-journal.json`と`.csw-write-*` | 中断した置き換えを完了するための記録と、設定を保存する一時ファイル |
| `~/.context-switcher-claude/native-code-launch-pending` | 起動対象と世代、一意の操作IDを含み、対象の起動確認か明示的な解除まで同期を止める予約 |
| `~/.context-switcher-claude/native-code-backups/` | 変更の同期前と起動予約の明示解除前の非公開バックアップ、保存先の一覧、共有設定、退避した起動予約 |
| `~/.context-switcher-claude/profiles/<環境名>/profile.toml` | その環境の名前・メモ・作成の記録・共有モード |
| `~/.context-switcher-claude/profiles/<環境名>/state.toml` | その環境をCSWから最初と最後に起動した日時 |
| `~/.context-switcher-claude/profiles/<環境名>/desktop-data/` | その環境のClaude Desktop App用データ |
| `~/.context-switcher-claude/profiles/<環境名>/cli-data/` | その環境のClaude Code用データ |

このほかに、設定ウィンドウは、表示のための次の3つの記録を、macOSがアプリごとに用意する画面データの保存場所に保存します。選んだアクセントカラーと、初回案内を表示したかどうかと、環境を初めて起動したあとに詳細画面に出るサインインの案内カードを閉じたかどうかです。案内カードの記録は環境ごとに持つので、環境を見分けるために環境名と作成日時を含めます。ここに入るのはこれらの記録だけで、環境のフォルダの中身やClaudeのデータは含まれません。

## CSWが読む場所

- 上の表にある自分専用のフォルダは、読み書きの両方を行います。環境の詳細画面でデータの内訳を表示するときも、読むのはこのフォルダの中のファイル名とサイズ・最終更新の日時だけで、ファイルの中身は開きません。共有リンクの先は合計に含めません。
- 既存のClaudeのフォルダ`~/Library/Application Support/Claude`と`~/.claude`は、次の場合にだけ触れます。
  1. **存在と空かどうかの確認**：フォルダやファイルがあるかどうかを調べます。環境の作成画面を開いたときは、既存のClaudeの2つのフォルダが空かどうかも調べます。このときは、フォルダの中の項目を1つ見つけた時点で調べるのをやめ、その項目の名前も使いません。ファイルの中身は読みません。
  2. **共有リンクの作成と張り直し**：環境の作成時と複製時に、共有を選んだ項目について、新しい環境の側に、既存のClaudeの実体を指すシンボリックリンクを作ります。分離の検査の修復コマンド`csw doctor --fix`も、リンク先が想定と異なってしまった共有リンクを宣言どおりの共有元へ張り直すか、共有元があるのに欠けている共有リンクを作るだけです。差し替えたり作ったりするのはリンクだけで、実体のファイルには触れません。ただし、空のフォルダだけは取り除きます。環境を作った時点で既存のClaudeに共有元のフォルダがまだ無かった場合、CSWは環境の側に空のフォルダを作っておきます。後から共有元ができたときは、`csw doctor --fix`がこの空のフォルダを取り除いてから共有リンクを作ります。フォルダを取り除く操作は中身が1つでもあると失敗するので、CSWはフォルダの中身を読まずに、空のフォルダだけを取り除けます。リンクを作るのも空のフォルダを取り除くのも環境のフォルダの中で、既存のClaude側には何も書きません。
  3. **コピー**：環境の作成時と複製時に、コピーを選んだ項目について、その項目のファイルを読み取り、新しい環境へコピーします。読み取るのはあなたが選んだ項目だけで、既存のClaude側は変更しません。
  4. **保存済みのClaudeの利用量**：下に挙げるDesktopのファイルを読みます。利用量のためにClaude Codeのフォルダを読むことはありません。
  5. **明示的に有効にしたローカルCode全体の共有**：下記のCodeストアを、既存のClaudeを含む全参加環境で読み取り、バックアップして置き換えます。サインイン情報は対象外です。
- 起動中のClaudeを見分けるために、実行中のプロセスの一覧と起動引数を読みます。起動を予約した場合も、この情報を繰り返し調べ、すべてのClaude Desktop主プロセスの終了と、起動後の対象環境の実行を確認します。作業の完了判定、プロセスのメモリや環境変数、画面、通信内容の読み取りは行いません。
- 前面に表示されているアプリの識別子は、メニューバーのアイコンから「いまの環境を確認」を押したときにだけ読みます。前面のアプリがClaudeの場合に、その起動引数からどの環境かを答えるためです。読むのはプロセスの識別子と起動引数だけで、画面の内容やウィンドウのタイトルは読みません。常時の監視には使いません。
- CSWのインストール用ディスクイメージがマウントされたままかを確かめるために、CSWの起動時と「取り出す」を押したときに、`hdiutil`でマウント中のディスクイメージの一覧を読みます。読むのは各ディスクイメージのファイルのパスとマウント先だけです。CSWのディスクイメージを名前で見分け、それ以外のディスクイメージは無視します。ディスクイメージの中身は読みません。

### Claudeの利用量のために読むローカルファイル

読み取り先は、見つかった各環境のDesktopデータの中に限定します。既存のClaudeでは`~/Library/Application Support/Claude`、CSWの環境では`~/.context-switcher-claude/profiles/<環境名>/desktop-data`です。この機能にアカウント名、メールアドレス、固定のアカウント一覧は組み込みません。

| Desktopデータ内のパス | 利用量の読み取りに使うもの |
|---|---|
| `plan-usage-history.json` | 保存済みの使用率、観測時刻、形式に含まれる場合は最新の観測の組織識別子 |
| `Cache/Cache_Data` | Chromium Simple形式のエントリー名、制限した長さのキーと形式情報、完全に一致する利用量の応答の本文 |

応答のURLは`https://claude.ai/api/organizations/<org>/usage`と、そのURLに`?skip_spend=1`だけを付けたものに限ります。組織識別子は、その環境の最新の履歴から取り、サインイン情報からは読みません。このURLはローカルキャッシュのキーとの照合にだけ使い、CSWから問い合わせることはありません。それ以外のキャッシュの本文や認証用のヘッダーは解析しません。組織識別子を持たない履歴は使用率の表示に使えますが、キャッシュ内の組織を推測するためには使いません。

同じ組織に属するアカウントでも、環境ごとに読み取りを分けます。対応するファイル形式と整合性を検査し、列挙するファイル数、読み取り量、展開量を制限します。シンボリックリンク・ハードリンク・通常ファイルでない入力は拒否します。未対応の形式や安全に読めない入力では、履歴だけの表示か未取得にし、認証情報や通信へ切り替えません。利用量を読む処理は、修復・コピー・書き込みを行いません。

画面に渡すのは環境名、使用率、時刻、記録元、表示状態だけです。生のキャッシュ、応答のURL、組織識別子を画面へ渡したり、ログやファイルに保存したりしません。読み取った利用量はメモリに保持し、CSW自身のキャッシュファイルを作りません。

最終確認時刻は保存された観測の時刻です。30分を超えた記録と、表示中のリセット時刻を過ぎた記録は古い記録として示します。欠けた値は未取得のままにし、リセット時刻を過ぎても使用率を0%に変えません。サインインを変えたあともキャッシュが残ることがあるため、いまサインインしているアカウントの確認には使えません。現在の利用量とアカウントは公式Claudeで確認してください。

## 手動終了を待ってから起動する

このフォークのローカルアプリは、Claude Desktopの実行中に、次の環境の起動を1つだけメモリに保持できます。CSWは終了要求、終了シグナル、Claudeのボタン操作、強制終了を行いません。作業と質問への回答を自分で終え、Claudeを通常どおり終了してください。ウィンドウを閉じただけでは終了しない場合があります。Accessibilityの許可やフックは使いません。

予約には、対象の環境と要求の識別子、状態、再検証に使うCSW自身の環境の設定を保持します。新しいファイルやブラウザの保存領域には書かず、CSWを終了または再起動すると消えます。キャンセルは終了待ちの間だけ行え、同期と起動が始まったあとは取り消せません。起動前に対象の環境とプロセスの停止状態を再検証し、その時点でプロセスを検査できなければ起動しません。起動要求を送ったあとは、検査に失敗しても起動を繰り返さず、起動の観測を続けます。起動を確認できない場合は、エラーを表示しても予約を保持し、キャンセル、置き換え、追加の起動を拒否します。対象が遅れて現れた場合は予約を完了します。CSWを再起動するとメモリ内の予約は消えますが、送信済みの起動や既存のCode共有の起動予約は取り消せません。

通常の起動経路では、前述のとおり選んだ環境と起動日時を保存します。ローカルCode全体の共有を有効にしている場合は、既存のバックアップ、処理記録、起動の予約も使います。これらは、手動終了を待つメモリ内の予約とは異なるものです。完全分離の「重複して起動」も同じキューを使い、他の環境の終了を待ちませんが、保留中の予約を飛び越えることはできません。「開き直す」は他の起動と直列に実行し、予約が保留中なら拒否します。新しいデータパス、OSコマンド、ネットワーク接続、認証情報の読み取りは追加しません。

## ローカルCode全体の共有

このフォークでは、会話履歴・プロジェクトのメモリ・入力履歴をすでに共有している環境に対し、`csw share-code --source default --replace <環境名>...`で追加の共有を明示的に有効にできます。読み書きする恒久的なCodeストアは、Desktopデータ内の`claude-code-sessions/<account>/<workspace>/`、`git-worktrees.json`、`ccd-session-presets.json`です。置き換え中は、同じCodeストアだけを含む`.csw-stage-*`と`.csw-previous-*`の兄弟フォルダ、`.git-worktrees.json-*`と`.ccd-session-presets.json-*`の一時ファイルも作ります。中断した場合は、非公開の処理記録と予定のCodeスナップショットを検証してからコピーを再開します。上書き前のデータもバックアップに残ります。保存されたCodeのツール権限、コネクタの参照、スケジュールタスクの定義、削除マーカー、ワークツリーの管理情報も含め、レコード全体を写します。Codeプリセットのアカウントキーは共有先に対応付けます。この操作のためにアカウント設定、Cookie、ブラウザストレージ、キーチェーンを開くことはありません。通信もClaude Code CLIへのサインインも行いません。

全Claude Desktopの終了と、各環境にアカウント・ワークスペースの組が1つだけあることを確認します。どのストアも置き換える前に、全ストアをバックアップします。リンク、ハードリンク、特殊ファイル、壊れたJSON、過大な入力、最終確認済みの参加環境以外の未知の内容変更は拒否します。以後は通常のSwitcherの起動処理で、最後に起動を確認した環境の完全な最新ストアを引き継ぎます。最初の起動確認前は、内容が変わったストアが1つ以下の場合だけ受け入れます。起動中のサイドバーへ注入する処理ではありません。CSWを使わない起動では同期しません。

共有するのは、ワークツリーの整理状態やスケジュールタスクを含むローカルCodeの内容と保存済みの動作です。クラウドProjects、クラウドChatの履歴、契約、コネクタのサインイン、Web側のカスタムグループは共有しません。参加環境は1つずつ使います。初期の元データと上書き前の共有先のデータは、ローカルのバックアップに残し、自動で間引きません。

以後の同期を無効にするには、全Claude Desktopを終了し、`csw unshare-code`を実行します。現在のローカルデータ、バックアップ、ログインは維持し、過去のストアへは戻しません。別途共有している会話履歴・メモリ・入力履歴のリンクも変更しません。参加環境の削除と完全削除は、共有グループを無効にしたあとに行えます。

起動を確認できなかった場合は、起動の予約を残して同期を止めます。全Claude Desktopの終了後に「終了後の起動予約を解除」か`csw recover-code-launch --abandon`を明示的に実行すると、全参加ストア・設定・予約を非公開バックアップへ保存し、停止状態と元データを再検証してから予約だけを退避します。共有、ストア、最後に起動を確認した記録は変更せず、起動も再送しません。未知の内容変更、保存先の不一致、未対応の予約、処理記録が残る場合は拒否します。コピーが中断していた場合は、処理記録にある予定のコピーを完了してから無効にし、上書き前のストアはバックアップに残します。

最後に起動を確認した参加環境を原子的に記録してから予約を解除します。保存直後に中断した場合は対応する予約だけを清掃し、未確認の起動は推測しません。旧設定の基準の検証には、指定された前回のバックアップのCodeスナップショットだけを読みます。JSONの整形、セッション直下の数値フォーカス時刻、worktreeのGC対象ディレクトリの数値時刻は内容の変更から除き、未知のフィールドは内容として比較します。既知の古い完全なストアは置き換え、未知の外部更新は停止します。中断後も、ストアの構成要素が元データか予定のコピーに一致するときだけ復元し、未知の更新は記録とバックアップを残して停止します。予定のコピーも元データと同じ非公開バックアップ内に保存します。起動の証拠を得るために認証ファイル、プロセス環境やプロセスメモリは読みません。


## 環境の複製について

環境の詳細画面にある複製は、選んだ環境のフォルダの中身を、あなたのMacの中で新しい環境のフォルダへそのまま写す機能です。写さないのは、アカウントのサインイン情報`config.json`、コネクタとアプリ設定、端末ID、セッションの実行状態といった常に分離する項目と、導入の記録が元の環境の場所を指すプラグインと、CSWが起動の日時を記録する`state.toml`だけです。シンボリックリンクはそのまま写さず、共有の項目は、既存のClaudeを指すリンクとして張り直します。このときもCSWが行うのはファイルをそのまま写すことだけで、中身を解釈したり、外部へ送ったりすることはありません。既存のClaudeを複製することはできません。

Claude Desktop Appは、サインインの状態を環境のフォルダのCookieにも保存しています。このCookieもほかのファイルと同じようにそのまま写るので、複製先のClaude Desktop Appは、複製元と同じアカウントでサインインした状態で開きます。複製元と複製先は同じサインインの状態を持つので、どちらかでログアウトすると、もう一方もログアウトされます。別のアカウントで使う環境は、複製ではなく「環境を作る」から作ってください。一方、ターミナルで使うClaude Codeは、サインイン情報を環境のフォルダの外にあるmacOSのキーチェーンに、環境ごとに分けて保存します。CSWはキーチェーンに触れないので、この情報は複製先に写りません。複製先のターミナルでClaude Codeを初めて使うときは、ログインし直してください。例外として、キーチェーンへ書けなかったときに限り、Claude Codeは環境のフォルダに`.credentials.json`を置きます。このファイルはほかのファイルと同じように写るので、その場合は複製先のClaude Codeも複製元と同じ資格情報を使います。

## CSWが実行するOSコマンド

CSWは次の4つのmacOS標準コマンドだけを実行します。いずれもローカルの操作で、通信しません。

| コマンド | 何のために使うか |
|---|---|
| `open` | 選んだ環境のデータフォルダを指定してClaudeを起動します。リンクを既定のブラウザで開くのと、環境のデータフォルダをFinderで開くのにも使います |
| `pgrep` | Claude Desktop Appが起動中かを調べ、起動の予約が手動終了を待つときにも使います |
| `ps` | Claudeのプロセスの識別子と起動引数から、実行中の環境、手動終了、予約先の起動を確認します |
| `hdiutil` | CSWのインストール用ディスクイメージがマウントされたままのとき、それを検出して取り出します |

## 決して触れないもの

- パスワードを保管するmacOSのキーチェーン。読み書きするコード自体がありません。
- サインインのトークン、ブラウザやClaudeのCookie。Claude Desktop Appのサインインの状態はその環境のフォルダの中にあり、CSWがその中身を開いて解釈することはありません。環境の複製で写すときも、そのまま写すだけです。Claude Codeは、サインイン情報をmacOSのキーチェーンに保存します。CSWはキーチェーンに触れないので、この情報を読むことも複製で写すこともありません。キーチェーンへ書けなかったときに限り、Claude Codeは環境のフォルダに`.credentials.json`を置きます。環境を複製すると、このファイルもほかのファイルと同じようにそのまま写ります。
- 上の「CSWが読む場所」に挙げた以外の、他のアプリのデータ。
- ネットワーク。送信も受信もしません。

## 自分で確かめる方法

### 通信していないことを確かめる

CSWを起動し、設定ウィンドウを開いた状態で、ターミナルで次を実行します。

```bash
lsof -i -a -p $(pgrep -f Claude-Desktop-Switcher | head -1)
```

このコマンドは、CSWのプロセスが開いているインターネット接続を一覧表示します。何も表示されなければ、接続はありません。

正確を期すための補足です。設定ウィンドウの描画は、macOSの仕組みによりWebKitという別プロセスが担います。CSWの画面はアプリに同梱したローカルファイルだけを読み込むため、そこにも外部への接続はありません。ただし、上のコマンドはアプリ本体のプロセスだけを見るため、このMac全体の通信まで含めて徹底的に確認したい場合は、`nettop`や通信を監視する専用アプリで、CSWに関係する接続が現れないことを観察してください。

### 配布物が本物であることを確かめる

Appleにアプリの身元を確認してもらう審査を公証といいます。ダウンロードしたCSWがこの審査を通ったものであることは、次のコマンドで確認できます。

```bash
codesign -dv --verbose=2 "/Applications/Claude-Desktop-Switcher.app"
spctl --assess --type execute -v "/Applications/Claude-Desktop-Switcher.app"
```

`spctl`が`accepted`と`Notarized Developer ID`を表示すれば、Appleの公証を通った配布物です。

### 分離とリンクの実体を確かめる

環境のデータが実際にどうつながっているかは、Finderやターミナルでそのまま見られます。

```bash
ls -la ~/.context-switcher-claude/profiles/<環境名>/cli-data/
```

共有を選んだ項目は、既存のClaudeの実体を指すシンボリックリンクとして表示されます。分離した項目は、その環境専用の実体ファイルとして表示されます。

### 依存ライブラリに通信機能が無いことを確かめる

「通信しない」を約束として書くだけでなく、依存ライブラリの段階で機械的に強制しています。リポジトリの`deny.toml`に、HTTPやWebSocketのクライアントライブラリの一覧を禁止として登録してあり、これらが依存に入るとCIのビルドが失敗します。この検査はすべてのプルリクエストで自動実行されます。

正直に書いておくべき点がひとつあります。依存関係の記録ファイルである`Cargo.lock`には、`reqwest`と`hyper`というHTTPライブラリの項目が載っています。これは、CSWの画面基盤であるTauriがWindowsとLinux向けの依存として宣言しているためで、macOS向けのビルドには含まれません。この事実はソースコードから次のコマンドで確認できます。

```bash
cargo tree --target aarch64-apple-darwin -i reqwest
cargo tree --target aarch64-apple-darwin -i hyper
```

`warning: nothing to print.`と表示されれば、そのライブラリはmacOS向けの依存関係に含まれません。

### 配布物の部品表（SBOM）を確かめる

v0.19.0以降の各リリースには、配布物に含まれる全ライブラリの一覧をCycloneDX形式で添付します。GitHubのリリースページから`csw-desktop_aarch64-apple-darwin.cdx.json`などのファイルをダウンロードすると、macOSビルドに含まれるすべての部品とバージョンを確認できます。
