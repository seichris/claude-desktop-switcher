# 背景と合意

利用者は更新後に既存のClaudeで開き直される現象を確認し、直前に利用していた環境へ自動で戻すよう明示的に依頼した。従来の案内だけの方針を、この任意機能に限って変更する。一般の環境切り替えは手動終了のままとする。

# 対象と規模

更新後の再起動を利用するローカル利用者が対象。常駐中のCSWが既存の観測ループで処理する。追加のデーモン、認証、ネットワーク、アクセシビリティ権限は使わない。設定はCLIで有効・無効を切り替える。GUIの構造は変更しない。

# 仕様

- 既定では無効。`csw update-return on|off|status`で設定し、この利用者には有効化する。
- 単独で動作していた名前付き環境の実プロセスと設定を観測し、元環境として記録する。選択中の行だけでは決めない。
- その環境の終了後90秒以内に、インストール済みClaude実行ファイルの識別子が変わり、環境の引数を持たない新しいClaude主プロセスが単独で現れた場合だけ対象とする。
- 直前と同じPID、通常のDock起動、設定無効、複数インスタンス、未知の環境、検査失敗、CSW起動時に既に動作中の既存のClaudeは対象にしない。
- 対象環境の設定、現行アプリ識別子、対象PIDと起動引数を直前に再検証する。共通LaunchQueueの排他区間で、対象の通常終了を1回だけ要求し、終了後の既存の同期・起動経路へ渡す。
- 強制終了は使わない。通常終了が拒否された場合は起動しない。起動送信の自動再試行も行わない。停止後の競合は既存の回復手順に従う。
- CSWが常駐している間の更新による再起動が対象。CSW不在時の遷移や、更新後にClaudeが再起動しない場合は推測で起動しない。

# ファイルと検証

coreに更新観測・設定・通常終了のOS境界とテスト、CLIに設定コマンド、desktopに既存観測ループとの接続を追加する。利用者向けガイド・プライバシー・LPは日英で同じ条件に更新する。SPECIFICATIONとLOCAL_BUILDも同期する。

- RED：更新再起動の復帰、通常起動の不介入、PID再利用・複数プロセス・期限切れ・検査失敗・設定変更の拒否。
- GREEN後：fmt、clippy、全crateのビルド、core/CLIテストの順に実行する。
- ネイティブの通常終了はNSRunningApplicationの公開APIを使い、強制終了APIを呼ばないことをソースで確認する。
- ローカルapp/CLIをビルドして旧版を退避後に導入する。有効設定とChrisの継続稼働を実地確認する。現在のClaudeを更新試験のために終了させない。

# リスクと制限

アプリが更新された直後に利用者が手で既存のClaudeを開いた場合、同じ観測条件になり得る。有効時にはこれも直前環境への復帰対象となる。古い履歴が既存のClaudeで実行されて内容を書き換えた場合は、安全のため同期で停止する。手動のアカウント変更と自動の更新復帰を区別するため、通常の起動には介入しない。
