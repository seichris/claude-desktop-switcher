# Desktopのローカル記録からClaudeの利用量を表示する

## 背景と判断

v0.17系の利用量表示はClaude Codeのstatuslineに依存しており、Desktopだけを使う環境では更新されなかったため撤去した。以前の調査と判断は[usage-display-removal.md](usage-display-removal.md)に残す。

現在のClaude Desktop Appは、利用量の記録を`plan-usage-history.json`に保存し、利用量の応答をHTTPキャッシュに残すことがある。このローカル記録を読む方法を採用する。認証情報やネットワークを使わず、最後に記録された値とその古さを表示する。サーバーの現在値をCSWが取得する機能ではない。

対象は、複数の環境でClaude Desktop Appを使い、環境を順に開かずに保存済みの利用量を見比べたい利用者である。GUIに一覧を設ける。Claude Codeの導入や追加のログインを前提にしない。

## ゴール

- 既存のClaudeと、CSWが発見したすべての環境を表示する。名前・アカウント・環境数を固定しない。
- 5時間と週間の使用率、記録されているリセット時刻、最終確認時刻を表示する。対応する追加の利用枠も、その記録があれば表示する。
- 古い値、欠けた項目、読み取れない記録を区別し、未取得を0%に見せない。
- 環境データとサインイン状態を変更せず、現在動いているClaudeを終了させない。

## 設計原則

利便性と引き換えに認証情報・通信の境界を広げない。CSW自身の通信、Cookie・トークン・キーチェーンの読み取り、サインインの再利用は行わない。読み取りは次の固定した場所と形式に限る。

1. 各環境のDesktopデータ内の`plan-usage-history.json`。v1は使用率と時刻、v2はそれらに加えて組織識別子を持つ。
2. 同じDesktopデータ内の`Cache/Cache_Data`。Chromium Simple形式のキーと構造を調べ、最新の履歴にある組織の`https://claude.ai/api/organizations/<org>/usage`、または同じURLに`?skip_spend=1`だけを付けた応答を読む。一般のキャッシュ本文や認証用のヘッダーは解析しない。

組織識別子はキャッシュの照合にだけ使い、画面やログに渡さない。同じ組織に属するアカウントでも、環境のデータルートをまたいで値を合わせない。サインイン中のアカウントを検証する目的で、認証ファイルを読むこともしない。

## 期待する挙動と受け入れ条件

1. 有効なキャッシュ応答では、使用率とリセット時刻を同じ応答から取り、HTTP応答の記録時刻を最終確認として表示する。ファイルの更新日時やCSWが読み直した時刻で新しく見せない。
2. 応答がない、形式が未対応、壊れている場合は、利用できる最新の履歴を使う。履歴からはリセット時刻を推測しない。より新しい履歴に、古い応答のリセット時刻を足すこともしない。
3. 記録から30分以内は新しい記録として扱う。30分を超えた記録、または表示中のリセット時刻を過ぎた記録は古い記録として示す。リセット時刻が過ぎても使用率を0%へ書き換えない。
4. `null`や欠けた値は未取得と表示する。使用率は有限の0〜100の数値だけを受け付ける。将来に大きくずれた時刻や未知のバージョンは採用しない。
5. 最新の履歴が示す組織だけを、その環境のキャッシュと照合する。他の組織や環境の値で穴埋めしない。組織を持たないv1の履歴ではキャッシュの組織を推測しない。
6. 環境を再ログインしても、以前のキャッシュが残ることがある。表示はその環境に残った記録であり、現在のサインインの確認結果ではないことを案内する。
7. シンボリックリンク・ハードリンク・通常ファイルでない入力を拒否し、ファイル数、読み取り量、入力サイズ、展開量を制限する。形式・長さ・整合性の検査に失敗したデータは採用しない。
8. 画面へ渡すのは環境名、状態、使用率、時刻、記録元だけとする。生のキャッシュ、URL、組織識別子、認証データを表示・永続化・ログ出力しない。
9. ローカル記録の再確認は読み直しだけを行う。ネットワーク要求、Claudeの起動、プロフィールの作成・修復・権限変更を伴わない。
10. 日本語と英語で同じ情報を表示し、環境名など利用者の値は翻訳しない。テストと公開画像は架空のデータだけを使う。

## 検証

仕様からテストを書いて失敗を確認したあと、実装で通す。欠損・破損・過去のリセット・新旧の競合・同じ組織を持つ異なる環境・リンク・過大な入力と圧縮データを含める。

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace
cargo test --workspace
python3 .github/scripts/ja_spacing.py --check
```

GUIでは新しい記録・古い記録・未取得を日英両方で確認する。差分のセキュリティレビューを行い、マージ後のビルドをインストールして確かめる。

## リスクと対応

- DesktopやChromiumの非公開の保存形式は変わることがある。未対応の形式で認証や通信に切り替えず、履歴へのフォールバックか未取得で示す。
- 古い記録やログイン前のキャッシュを現在値と誤解しないよう、記録時刻と状態を常に添える。現在値が必要なら、対象の環境で公式Claudeの利用量画面を確認する。
- キャッシュを信頼できる入力と扱わず、読み取りと展開を制限する。破損したファイルやリンクをたどらない。

## スコープ外

- ネットワークによる利用量の更新、認証情報の抽出、追加ログイン、ブラウザ操作、Claude Codeのstatusline設定。
- 使用量からの料金推定、リセット後の残量推定、アカウント間のデータ合算。
- Chat履歴やCode履歴の移動・共有設定の変更。
