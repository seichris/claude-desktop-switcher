# 手動終了を待って次の環境を起動する

## 背景と合意

通常の起動操作はClaude Desktop Appの実行中に環境を変更できません。共有ファイルの衝突を防ぐための制約です。ユーザーは、作業と回答待ちを自分で確認してClaudeを終了し、CSWが終了後に選んだ環境を開く方式を承認しました。終了操作を自動化する実験はPR #5に分離し、この変更には取り込みません。

対象は、Claude Desktop AppをGUIから使い、次の環境を選んでから現在の作業を終えたい利用者です。手動終了の案内だけでなく、終了後の起動を予約する小さなGUI機能を採用します。CLIの使い方と認証方式は変えません。

## ゴール

1. 別の環境を選び、通常の起動操作を押すと、Claudeが実行中なら終了待ちになります。
2. 予約先とキャンセル操作を設定ウィンドウに表示します。
3. 利用者が作業と質問への回答を終えてClaudeを通常終了し、すべてのDesktop主プロセスが終了した後だけ、既存の同期・起動経路を実行します。
4. 起動中の対象環境を選んだ場合は、従来どおり前面に表示します。完全分離の「重複して起動」は維持します。

## 設計原則と承認済みの仕様

- セキュリティ・プライバシーを利便性と引き換えにしません。CSWはClaudeへ終了要求やシグナルを送りません。強制終了、Accessibility、フック、タスク検出、ネットワーク、資格情報の読み取りは追加しません。
- 判定対象はDesktop主プロセスの終了です。作業が完了したかは判定しません。ウィンドウを閉じただけでは終了しない場合があるため、Claudeメニューの終了またはCmd+Qを案内します。
- 予約はCSWプロセスのメモリだけに保持します。再起動後に復元せず、設定ファイルやブラウザの保存領域へ書きません。再起動は送信済みの起動や既存のCode共有の起動予約を取り消しません。
- 予約は同時に1つだけです。同じ対象への要求は現在の予約を返し、別のワーカーを作りません。別の環境へ変えるときは先にキャンセルします。
- キャンセルできるのは終了待ちの間だけです。同期と起動へ進む境界を排他的に確定し、キャンセル後や古い予約のワーカーは起動できません。
- 起動の実行前にプロセスを検査できなければ起動しません。対象環境の存在と設定を起動直前にも検証し、変更や削除があれば予約を失敗として表示します。
- 同期と起動は既存の停止状態を検査する経路を使い、途中でClaudeが再び起動した場合にも実行中のデータへ同期しません。
- ログインは各環境の既存のDesktopログインを使います。追加のClaude Code CLIログインは不要です。CLIの厳格な実行中拒否は維持します。

### GUIとトレイの契約

共通の`LaunchQueue`を使います。Tauriコマンドは`request_environment_launch(name)`、`get_pending_launch()`、`cancel_pending_launch(requestId)`で、状態の変更は`pending-launch-changed`で通知します。状態は`idle`、`waiting`、`switching`、`completed`、`canceled`、`failed`です。予約先と`request_id`、終了待ちの有無を示す`wait_for_exit`を返し、失敗には秘密情報や生のOSエラーを含めない固定のコードを使います。起動要求の送信後も対象の主プロセスを観測するまで予約を保持します。正常なプロセス検査でも10秒以上起動を観測できなければ、`launch_unconfirmed`で`failed`を表示して予約を残します。キャンセル、置き換え、再送を拒否し、観測だけを続け、遅れて対象が現れた場合は完了にします。送信後の観測失敗や不確実な起動エラーでも再送しません。完全分離の重複起動も同じキューで直列化しますが、`wait_for_exit: false`で他のClaudeの終了を待ちません。「開き直す」はキューの実行ロックを使い、予約が保留中なら拒否します。

## 変更ファイルと分担

| 対象 | 内容 |
|---|---|
| `crates/core` | 停止状態の再検証と既存の同期・起動経路の利用。必要な境界テスト |
| `crates/desktop/src` | 1件のメモリ内予約、世代番号、終了待ち・実行中・完了・失敗状態、キャンセル、GUIとトレイの共通経路 |
| `crates/desktop/ui` | 日英の終了待ち表示、予約先、キャンセル、完了と失敗の案内 |
| `crates/cli` | 新しい予約機能は追加しません。実行中の切り替え拒否を維持します |
| `docs/SPECIFICATION.md`、日英ガイド、日英プライバシー文書、`README.md` | 終了の主体、予約の寿命、プロセス情報の用途、既存の同期との関係を一致させます |
| `website/index.html`、`website/ja/index.html` | ローカル版の予約機能と手動終了の説明を同じ構造で更新します |
| `website/assets/*.png` | 統合後にCIのappshotから日英12枚を再生成し、LPの実寸とキャッシュバスターを更新します |

## 実装と検証の手順

1. 予約、重複、キャンセル、古いワーカー、検査失敗、対象の変更・削除、全Desktop終了後の1回だけの起動を仕様からテストします。失敗を確認してから実装します。
2. GUIとトレイから同じ終了待ち経路を使い、CLIは変更しません。
3. 同期・起動の直前に停止状態と対象を再検証します。検査ができないときは起動しません。
4. 日英UI、ガイド、プライバシー文書、README、LPを照合します。資格情報、画面の内容、タスクの状態を読まないことをコードで確認します。
5. 使い捨てのプロセスとテスト用の環境で待機、キャンセル、自然終了後の起動を確認します。利用者のClaudeタスクを停止・終了して検証しません。
6. 日英UIとLPを実描画し、LPは360、390、1024、1200、1440pxで横溢れを検査します。出荷用スクリーンショットを再生成します。
7. ローカル検証とセキュリティレビュー後、別の製品PRを作成し、CIを通してからマージします。PR #5は`[experiment]`のDraftとして保持します。

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace
cargo test --workspace
python3 .github/scripts/ja_spacing.py --check
```

## リスクと対応

| リスク | 対応 |
|---|---|
| 作業中にClaudeを終了してしまう | CSWは終了操作をしません。利用者が作業と質問への回答を確認して終了します |
| ウィンドウだけ閉じて待ち続ける | Claudeの終了とCmd+Qを案内し、キャンセルを常に見える場所に置きます |
| 予約の二重実行、キャンセル後の起動 | 単一予約、世代番号、実行開始の排他境界をテストします |
| Claudeが終了後に別経路から再び起動する | 既存の同期・起動処理の停止検査で拒否し、予約の失敗を表示します |
| 予約対象が削除・変更される | 実行前に対象を再検証して拒否します |
| 古い案内や画像が自動終了を示唆する | 日英の全サーフェスと12枚のスクリーンショットを確認します |

## スコープ外

- Claudeの自動終了、未完了タスクの検出、終了ガードの検証・操作。
- Claude本体の改変、追加ログイン、認証情報の移動、ログや画面内容の解析。
- PR #5の実験コード、CLIへの予約機能、予約の永続化。
- クラウドのChatとProjectsの同期、共有設定の新規変更。
